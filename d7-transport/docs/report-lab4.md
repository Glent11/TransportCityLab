# Отчёт по лабораторной работе №4
## «Шина событий: публикация и приём»

**Район:** d7-transport (Транспорт)
**Тема:** Реализация обмена событиями через учебную шину.

### 1. Цель работы

Настроить публикацию и приём событий через учебный брокер, реализовать проверку подписи, контроль времени события, защиту от повторной обработки и проверить восстановление доставки после сбоя брокера.

### 2. Установка и настройка учебной шины

В репозиторий района были добавлены каталоги `bus/`, `broker/` и `scripts/`.

Для запуска учебного брокера использовалась команда:

```bash
python3 broker/local_broker.py
```

Брокер работал по адресу:

```text
http://127.0.0.1:14167
```

В корне проекта был создан файл `.env` с настройками `BUS_BROKER` и `BUS_KEY`. Файл `.env` не добавляется в Git, так как содержит секретный ключ.

### 3. Реализация продюсера

В файле `bus/producer.py` настроена публикация события района Транспорт.

Используемый тип события:

```text
city.transport.delivery.failed.v1
```

Тема публикации:

```text
city.events.transport.delivery.failed
```

Источник события:

```text
/d7-transport/api
```

Для демонстрации была выполнена команда:

```bash
python3 bus/producer.py demo
```

Публикация завершилась успешно. В журнале появилось событие `event.published`.

### 4. Реализация консьюмера

В файле `bus/consumer.py` настроен приём и обработка событий.

Перед обработкой выполняются три проверки:

1. Проверка HMAC-подписи события.
2. Проверка актуальности времени события.
3. Проверка уникальности идентификатора события по журналу `processed.jsonl`.

При успешном прохождении проверок событие обрабатывается, состояние сохраняется в `state.json`, идентификатор записывается в журнал, после чего отправляется подтверждение брокеру (`ack`).

Обработчик реализован с учётом идемпотентности: повторная обработка одного и того же события не должна создавать дублирующие записи.

### 5. Ручная проверка обмена событиями

Была запущена пара продюсер–консьюмер через учебный брокер.

Продюсер успешно опубликовал событие типа `city.transport.delivery.failed.v1`.

Консьюмер принял событие, выполнил обработку и сохранил результат в `state.json`. Идентификатор обработанного события был записан в `processed.jsonl`.

Таким образом, ручная проверка публикации и приёма завершилась успешно.
