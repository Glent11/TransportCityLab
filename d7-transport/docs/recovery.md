# Восстановление района 7 — Транспорт

## 1. Зависимости

Для восстановления района необходимы:
- копия репозитория `d7-transport.bundle`;
- Python 3;
- Docker и Docker Compose;
- файл `.env`, хранящийся отдельно от Git;
- резервная копия базы данных (если используется).

Резервная копия базы данных:
- СУБД: PostgreSQL 16.
- Расположение: Docker volume `db-data` (основные данные); резервная копия — `backups/transport.sql`.
- Периодичность создания: ежедневно и перед обновлением системы.

## 2. Секреты

Файл `.env` хранится отдельно от Git у ответственного участника команды: `<Даниловой Марии Олеговна>`.

В файле должны быть настроены:
- `BUS_BROKER=http://127.0.0.1:14167`;
- `BUS_KEY` — секретный ключ HMAC.

`BUS_KEY` не является TLS-ключом `tls/private/district.key` из лабораторной работы № 2.

Файл `.env` исключён из Git. Секреты нельзя помещать в коммиты, отчёты и общие чаты.

## 3. Порядок запуска

1. Получить копию репозитория и перейти в рабочую папку:
   `git clone d7-transport.bundle d7-transport && cd d7-transport`
2. Восстановить файл `.env` из защищённого места хранения, не из Git.
3. Запустить сервисы района:
   `docker compose up --build -d`
4. Запустить брокер событий:
   `python3 broker/local_broker.py`
5. Проверить наличие резервной копии базы данных `backups/transport.sql`.
   При её наличии восстановить данные командой:
   `docker compose exec -T db psql -U transport -d transport < backups/transport.sql`.
6. Убедиться, что производитель и потребитель событий могут подключиться к брокеру.

## 4. Проверка после восстановления

1. Проверить доступность сервиса:
   `curl -s http://127.0.0.1:8080/health`
2. Ожидаемый ответ:
   `{"status": "ok"}`
3. Проверить работу шины событий:
   `./scripts/check-bus.sh`
4. Ожидаемый результат автоматической проверки: 9 из 9.
5. Проверить журналы производителя и потребителя, убедиться в корректной обработке событий и защите от повторной обработки.
