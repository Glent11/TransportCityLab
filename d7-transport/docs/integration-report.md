# Отчёт об интеграции межрайонной шины событий
## Район 7 «Транспорт» — Район 3 «Мэрия»

### 1. Цель интеграции

Целью проверки являлась демонстрация обмена событиями между информационной системой района 7 «Транспорт» и принимающим узлом района 3 «Мэрия» посредством межрайонной шины событий.

Проверялась передача уведомлений о сбоях доставки, проверка подлинности сообщений, получение события принимающей стороной и фиксация результата обработки.

### 2. Участники обмена

- Отправитель: район 7 «Транспорт».
- Получатель: район 3 «Мэрия».
- Тип взаимодействия: асинхронная передача событий через брокер.
- Тема: `city.events.transport.delivery.failed`.

### 3. Передаваемое событие

В ходе проверки было сформировано событие типа:

`city.transport.delivery.failed.v1`

Событие содержало:
- идентификатор события;
- источник `/d7-transport/api`;
- целевой адрес `/d3-cityhall/api`;
- причину сбоя `timeout`;
- количество попыток доставки — 2;
- время первого и последнего обнаружения сбоя.

Передача выполнялась с использованием цифровой подписи HMAC-SHA256.

### 4. Результаты проверки

В журнале отправителя зафиксировано событие `event.published` со статусом `success`.

Принимающий consumer района 3 получил сообщение и успешно выполнил его обработку.

В журнале принимающего узла зафиксированы:
- `data.change` — событие сохранено идемпотентно;
- `event.consumed` — событие успешно обработано.

Результат обработки: получено и обработано 1 сообщение.

Последовательность журналов подтвердила прохождение события от producer района 7 до consumer района 3 и успешную фиксацию результата обработки.

### 6. Вывод

В рамках интеграционной проверки продемонстрирован полный цикл межрайонного обмена: формирование события, его подписание, публикация в брокере, получение принимающим узлом и идемпотентная обработка.

Проверка подтвердила работоспособность реализованного механизма обмена событиями между узлами районов 7 и 3 в тестовой среде.
