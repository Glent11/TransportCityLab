Что модель сделала хорошо:

- Корректно настроила ssl_protocols TLSv1.2 TLSv1.3.

- Правильный редирект с 80 на 443.

- server_name только для своего района.

- Нет лишних путей и autoindex.

Что плохо:

- Нет HSTS.

- Нет server_tokens off.

- Не указаны ssl_ciphers - хотя для TLS 1.3 шифры не настраиваются, для TLS 1.2 стоит явно ограничить.

- Не упомянуты права 600 на ключ и проверка, что ключ не в Git.

- Не сказано про срок сертификата и что он не самоподписанный.

Что выдумала: Ничего критичного не выдумала.

Модель в целом справилась с базовой настройкой TLS и генерацией сертификатов, корректно указав протоколы (TLS 1.2/1.3) и механизм редиректа. Однако она упустила важные элементы защиты, такие как HSTS, скрытие версии сервера (server_tokens off) и явное ограничение шифров для TLS 1.2. В ответе про OpenSSL модель допустила неточность, установив срок действия сертификата в 825 дней, что противоречит рекомендациям чек-листа («месяцы, не годы»). Опасных советов (отключение проверки, -k, verify=False) модель не предлагала.

| **Строка в ответе ИИ**                           | **Что не так**                                   | **Какая атака / риск**                       | **Как исправить**                                                                           |
| ------------------------------------------------ | ------------------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Отсутствует add_header Strict-Transport-Security | Нет HSTS                                         | SSL Stripping (понижение до HTTP)            | Добавить add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always; |

| Не указан ssl_ciphers для TLS 1.2                | Используются дефолтные шифры (могут быть слабые) | Компрометация шифра                          | Добавить ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:...';       |
| -days 825 в команде openssl x509                 | Срок действия более 2 лет                        | Долгий период компрометации при утечке ключа | Уменьшить до -days 90 (или 180)                                                             |
| Нет явного указания прав в конфиге Nginx         | Ключ может быть доступен другим пользователям    | Кража приватного ключа                       | Убедиться, что в Docker/системе права 600 и владелец - процесс Nginx                        |

Исправленная конфигурация Nginx

server_tokens off;

server {

    listen 443 ssl;

    server_name bank.city.lab;

    ssl_certificate     /certs/district.crt; _# Убедиться, что это полная цепочка (лист + промежуточный)_

    ssl_certificate_key /certs/private/district.key; _#_ _Права_ _600,_ _владелец_ _nginx_

    _# Только безопасные протоколы_

    ssl_protocols TLSv1.2 TLSv1.3;

    _# Явное ограничение шифров для TLS 1.2 (для 1.3 Nginx использует свои дефолтные)_

    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384';

    ssl_prefer_server_ciphers on;

    _# HSTS (заставляет браузер использовать только HTTPS)_

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    location / {

        proxy_pass http://api:8080;

        proxy_set_header Host $host;

        proxy_set_header X-Real-IP $remote_addr;

        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_set_header X-Forwarded-Proto $scheme;

    }

}

server {

    listen 80;

    server_name bank.city.lab;

    _# Редирект на HTTPS_

    return 301 https://$host$request_uri;

}
